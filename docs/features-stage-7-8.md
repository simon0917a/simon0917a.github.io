# 通知、效能與離線處理

## 交通通知中心

- 通知中心由首頁右上角鈴鐺開啟，不佔用底部導覽位置。
- 只顯示能由官方資料準確配對至指定路線或車站的巴士服務消息，不會從 ETA 推測交通事件。
- 九巴／龍運與城巴 ETA 資料沒有公告端點；通知中心另外讀取運輸署實時「特別交通消息（第二代）」XML。
- 只有正文明確提及巴士、巴士站或公共交通服務受改道、暫停、封閉、延誤等影響的項目才會顯示。純道路事故或一般交通繁忙不會靠位置推測成巴士通知。
- 排序依次為收藏路線、附近車站及其他明確影響巴士服務的消息；已讀識別碼儲存在 `localStorage` 的 `香港巴士已讀通知`。
- 通知介面與資料只有在開啟通知中心時延遲載入。

## 更新、快取與離線狀態

- 首頁先讀取 `localStorage` 的 `香港巴士最後成功附近資料`，只接受 24 小時內及距離目前查詢位置不超過 1 公里的資料，再於背景取得最新 ETA。
- 首頁與路線詳情在頁面可見時每 25 秒更新；切到背景時不發出 ETA 請求，返回前景後立即更新。
- 手動重新整理會繞過伺服器的新鮮 ETA 快取；同一頁 10 秒內的重複操作會被攔截。
- ETA 倒數由前端分鐘時鐘按 `etaTime` 重算，不需要因此呼叫 API。
- 更新失敗時保留最後成功資料，並以「上次成功資料」及實際更新時間標示，不會把舊資料偽裝成即時結果。
- Service Worker 只為導覽及同源靜態資源提供離線殼層；`/api/` 請求保持網路優先且不會錯誤回傳 HTML。

## 品質驗證

- TypeScript 型別檢查、Vitest 測試及 Vite 正式建置都必須通過。
- 正式建置應保留搜尋頁與通知中心的獨立延遲載入檔案。
- 以 320px 及 430px 手機寬度檢查三個底部分頁、首頁資料層級、最近車站詳情、收藏、路線號碼鍵盤、通知空狀態、舊資料提示及水平溢位。
